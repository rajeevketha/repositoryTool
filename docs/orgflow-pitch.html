OrgFlow

Move Salesforce config
the way configurators work

Build a field, a layout, a flow in a sandbox. Send that same named package to QA, then prod — in Chrome. No project setup. Git is optional.

A sequential From → To promotion tool. Not a second IDE. Not a DevOps platform.

The gap

A field change should not require a repo

What configurators actually ship

Custom fields, record types, layouts, Lightning pages, flows, permission sets, validation rules. Named members. One hop at a time: DEC → QA → Staging → Prod.

What most tools ask for

A DX project, a CLI, a change set, or a release train. Fine for developers. Heavy when you just built Account.Status__c and need it in QA today.

Who it is for

Salesforce configurators first

Admins & configurators

Pick members by name. Tick what you just built. Deploy. Stay in the browser where you already work.

Small teams

Keep snapshots on this device. Promote the same package to the next org. Jira is optional.

Teams with a repo

Turn on GitHub, GitLab, or Azure when you need a shared warehouse. Same wizard. Jira becomes required.

How it works

Four steps. You cannot skip ahead.

1 · Start
Detect orgs

Log into From and To in Chrome. Detect. They must be different. Choose this device or a release repo.

2 · Package
Tick members

What’s new in the From org. Search a type if you know the name. Add a related layout in one tap — not every layout.

3 · Retrieve
Pull the files

Retrieve from From. Download a zip if you want. Compare with a saved snapshot. Then Next.

4 · Confirm
Validate / Deploy

See From → To, what is going, already-in-To, then dry-run or send. Result stays on the screen.

Workbench retrieves. OrgFlow promotes.

Versus other deploy / repo tools

Not Copado. Not Gearset. Not a change set.

Change Sets

Upload, wait, download, remember dependencies. OrgFlow is named members, one hop, result on the same screen. No outbound/inbound pair to babysit.

Copado / Gearset / Flosum

Release trains, dependency graphs, data, user seats. OrgFlow does not replace them. It does the small promotion those platforms make expensive: this field, this layout, this org, now.

Git-only tools

A repo without a picker is still a developer workflow. OrgFlow can write Jira versions into GitHub, GitLab, or Azure — after you picked members in the UI.

What OrgFlow will not do

No records / data deploy. No full org compare. No automatic dependency graph. Tick the members you know you built.
